# Repo standards: one format for playbooks, records and tools (general)

Written 2026-10-20. Goal: everything this repo produces is **offline-first, plain files, checkable by a script**, so that any assistant (a Hermes-style agent later, or a person today) can read it the same way.
Nothing here depends on a model. Where an outside standard exists it is reused; the agent-skills details were read from a search summary of the official page and must be **checked against the live spec**.

## 1. Principles

1. Plain text in git (Markdown, YAML, CSV, JSON). No database needed to read it.
2. **Every fact has a source and a date**: an official link, an "as of" date and an expiry date. Volatile numbers (prices, fees, thresholds) are stored with where to look them up, not as timeless truth.
3. **Pointers, not copies**: link to the official page; do not paste text that has no licence.
4. **Privacy split**: general method goes in `docs/` and `data/`; a person's own facts go only in `private/` (ignored by git). The privacy scan runs on every commit.
5. English in the repo; the user-facing text is produced in the user's language at answer time.
6. Cheapest first: scripts and data before a model; a model only to phrase, never to invent numbers, links or contacts.
7. Dates are ISO (`2026-10-20`); money is `ARS` with the as-of date; units are normalised (section 5).

## 2. Playbook (a guide in `docs/`)

Markdown file with YAML front-matter:

```yaml
---
id: traffic-fines            # lowercase, hyphens
title: Traffic fines in Argentina
audience: person             # person | helper
country: AR
region: ""                   # province or city when it is local
language: en
topics: [fines, transport]
sources:                     # official first
  - {name: "...", url: "https://...", kind: official, read_on: 2026-10-20}
as_of: 2026-10-20
expires: 2027-04-20          # after this date the page is "stale" and must be re-checked
status: draft                # draft | reviewed | stale
licence: CC-BY-4.0           # for the text we write
verified_by: ""              # empty until a human reviewed it
not_verified: ["..."]        # open items, mirrored in the page
---
```

Body sections, in this order: what it is and why it matters (cost), where to check, how it is calculated, **how to pay the least**, risks, not verified. A page past `expires` is rendered with a stale warning and never quoted as current.

## 3. Directory record (free resources: food, legal help, shelter, utilities help)

A directory is a CSV or YAML list following the **Open Referral HSDS** shape with a stricter minimum profile (HSDS is CC BY-SA 4.0; check the licence before copying its text). Minimum fields:

| field | rule |
|---|---|
| `id` | stable, unique |
| `name`, `description` | plain language |
| `category` | from a small fixed list (OpenStreetMap-style tags such as soup kitchen or food bank may seed it) |
| `contact` | at least one of phone, address, web, messaging; **never generated by a model** |
| `schedule` | opening hours or "ask" |
| `area` | the locality served |
| `source`, `source_url` | where the record came from |
| `last_verified` | ISO date; older than 180 days = hidden or flagged |
| `verified_by` | method: phone, visit, official page |
| `status` | active | unverified | closed |

A report-a-problem queue (a file or issue label) is reviewed by a person before any change.

## 4. Price records (the grocery planner, `GROCERY_PLANNER.md`)

Two tables, joined by the barcode:
- `product`: `ean` (barcode, GTIN), `name`, `brand`, `category`, `size_value`, `size_unit` (g, kg, ml, l, unit).
- `price`: `ean`, `store_chain`, `store_id` (branch or locality), `price`, `list_price`, `promo_text`, `promo_kind`, `promo_conditions` (include `requires_membership` and `payment_method` when a discount needs a loyalty card, a bank card, a wallet or a weekday), `valid_from`, `valid_to`, `source`, `source_kind` (`sepa` | `chain_catalog` | `manual` | `wholesale_report`), `retrieved_at`.
Derived: `unit_price` per kg, per litre or per unit, always computed from the two tables, never typed in.

## 5. Normalisation

- Weight in kg, volume in l, count in units; compare **unit price**, not shelf price.
- Currency ARS; every price carries `retrieved_at`; a price older than 7 days is "stale" for planning.
- Names: lowercase ASCII keys for ids; display names keep accents.

## 6. Tools as skills (for an agent later)

Use the open Agent Skills layout, which Hermes reads: a folder per skill with a `SKILL.md` (YAML front-matter plus Markdown instructions) and optional `scripts/`, `references/`, `assets/`.
- Required front-matter (per the public spec): `name` (max 64 chars, lowercase letters, digits and hyphens, not starting or ending with a hyphen) and `description` (max 1024 chars, what it does and when to use it). Optional: `license`, `metadata`.
- Keep `SKILL.md` under about 500 lines; put the bulk in `references/`.
- Every skill must run **without a model** where possible (a script does the work; the model only phrases the answer) and must refuse when its data is stale.
- Planned skills: `playbook-lookup`, `directory-search`, `fine-calculator`, `grocery-price-lookup`, `grocery-weekly-list`, `bill-triage`.

## 7. Checks (to be scripted, cheap and offline)

1. Front-matter present and valid; `as_of` and `expires` are dates; `expires` is later than `as_of`.
2. Every playbook has at least one official source with a `read_on` date.
3. No personal data (the privacy scan) and no link that returns an error (a link check, run on demand).
4. Directory: required fields present; `last_verified` within 180 days for `active`.
5. Prices: `unit_price` recomputes from the base fields; no negative or zero prices.
6. Skills: name and description limits.
